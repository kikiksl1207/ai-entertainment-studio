# 2026년 10월 2일 검수 묶음 운영 반영

## 1. 목적

밤 동안 검증한 스토리 제작·승인·그림 지침·읽기 기록·현재 루트 추억,
아티스트 공개 데이터, 관리자 조회와 선택극장 개선을 실제 사이트까지 연결한다.
사용자는 검수된 Git 업로드·Pages/Render 배포·필요 DB 이관을 승인했고,
잘못된 Render 빌드 명령을 정상 명령으로 고치는 것도 별도로 승인했다.
유료 AI 생성·결제·계정 권한 변경은 이번 반영에 포함하지 않는다.

공개 파일 묶음은 명시한 548개 파일만 복사한다. 서버 소스, 시험 자료, 개발 문서,
비밀 설정, 보류한 이미지와 원본 제작 폴더는 사이트 파일에 포함하지 않는다.
E 저장소와 공유 원본은 삭제하지 않는다.

## 2. 동작

- 화면 계약 검사: 1,975개 통과, 4개 건너뜀. 실패한 과거 캐시 버전 검사만 수정했다.
- 공개 묶음 경계 검사: 27개 통과. 경로 탈출·연결 폴더·누락·변조·기존 결과 덮어쓰기를 거절한다.
- 실제 공개 파일 묶음: 548개, 949,518,209바이트. 복사 후 파일 내용 지문을 대조했다.
- 깨끗한 별도 서버 빌드: 종료 0. 기존 공유 빌드 폴더를 삭제하거나 재사용하지 않았다.
- 수정한 두 시험 파일의 집중 타입 검사: 종료 0. 모든 시험 파일까지 한꺼번에 타입 검사한
  시도는 2GB 검사 메모리 한도로 종료돼 전체 타입 검사 통과로 표시하지 않는다.
- 전체 서버 실행 검사: 225개 시험 묶음 통과. 두 묶음의 오래된 시험 입력을 수정한 뒤
  그 두 묶음의 158개 검사를 모두 통과했다. 앞 검사와 재검사의 중복 결과를 합산하지 않는다.
  격리 DB 등 별도 실행 조건이 필요한 53개 묶음·692개 검사는 이번 전체 실행에서 건너뛰었다.
- 최초 전체 서버 검사 프로그램의 메모리 한도 종료를 보존했다. 최종 실행은 작업자 1개와
  시험 묶음 사이 메모리 회수, 별도 타입 검사로 나누었다. 이는 운영 API의 메모리 사고가 아니다.

## 3. 연결

배포 전 실제 DB에는 81개 이관이 완료돼 있었고 실패 이력은 0개였다.
읽기 전용 검사에서 잘못된 임시 부모 테이블·고아 원고 청크·부적합 챗 유형·예상 밖 새 테이블은
각각 0개였고 원고 청크 연결 제약은 존재했다. 새 이관 18개는 기존 이관 파일을 수정하지 않고 추가한다.
Render DB 복구 화면에서 10월 2일 09:49 KST 전체 내보내기 파일 생성 완료를 확인했다.
서명된 다운로드 주소나 실제 개인정보는 이 문서에 기록하지 않는다.

잘못 저장된 `buildyarn`을 `npm install && npm run prisma:generate && npm run build`로
수정했고, 해당 명령으로 이전 버전의 빌드·배포가 성공한 것을 확인했다.
시작 명령은 기존 `npm run render:start`를 유지하며 정상 배포에서 seed는 실행하지 않는다.
기존 결제 실패 알림은 남아 있으며 결제 수단·요금제·권한·비밀 설정은 수정하지 않았다.

새 코드 운영 반영과 실제 화면 확인 결과는 아래에 이어 기록한다.
DB 내보내기 생성은 복원 훈련 완료를 뜻하지 않는다. 필요하면 이전 성공 배포로 앱을 되돌리고,
DB 전체 복원은 그 이후의 쓰기 손실과 복구 시점을 별도로 판단해야 한다.

## 4. 이해

Git에 코드를 올리는 것, 서버가 새 코드를 실행하는 것, 화면이 실제 데이터를 보여주는 것,
AI가 좋은 장면을 만드는 것은 각각 다른 확인 단계다. 이번에는 비용을 쓰는 생성 기능을
새로 켜지 않고 검증한 기능과 승인 경계를 운영까지 연결한다.
원고나 작가 기준이 바뀌면 과거 승인을 그대로 재사용하지 않으며, 캐릭터 추억은 현재 루트에서
확인한 사건만 사용한다. 실제 AI 문체·인물·시간선·그림 품질과 유료 생성 완주는 별도 미완료다.
