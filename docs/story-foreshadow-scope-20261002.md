# 2026-10-02 스토리 복선과 현재 루트의 사건 분리

## 1. 목적

작가가 승인한 복선은 참고하되, 복선이 나온 파트를 읽었다는 이유만으로
예고된 미래 사건까지 이미 겪은 일로 처리하지 않는다.

독립 QA가 확인한 재현: 1부에서 어머니가 살아 있고, 같은 1부에 연결된
승인 복선에는 "원작 32부에서 어머니가 죽는다"는 계획이 있다.
기존 요청은 이 복선을 일반 기억으로 보내 과거 사건과 혼동할 수 있었다.
작품 전체 생성 설정에는 이미 출처/계획 구분이 있지만, 별도로 저장된
복선 기억의 분류에도 같은 구분이 필요했다.

## 2. 동작

- 새 요청은 도달한 파트의 복선도 `author_plan_foreshadow`로 전달한다.
- 실제로 도달한 사건 기억과 작가 문체 표본은 기존 역할을 유지한다.
- 해당 분류를 요청의 지문과 저장된 기억 목록에 포함한다.
- 구형 대기 작업에 일반 사실로 분류된 복선이 있으면 유료 호출 전에 중단한다.
  저장된 요청을 몰래 수정하거나 예전 요청을 자동으로 유료 재시도하지 않는다.
- 요청/재조립/제공자/작업자 관련 4묶음: 169개 통과, 1개 건너뜀.
  이는 모의 제공자를 사용한 구현 검사이며 실제 소설 품질 합격이 아니다.
- 운영 소스 타입 검사: 종료 0. 첫 768 MiB 제한 시도는 메모리 부족으로 종료했고,

## 3. 연결

DB 구조, 저장된 원고, 기존 승인, 계정 권한, 설정은 변경하지 않는다.
새 요청의 분류와 지문이 함께 바뀌므로 예전 의미의 공유 결과를 동일 요청으로
오인하지 않는다. 구형 작업의 실패 복구는 기존 작업자/반환 절차를 사용한다.
사용자는 이번 검증된 서버 수정의 Git 업로드/운영 배포를 별도로 승인했다.

그림 비용 승인을 확대하거나 공개 제공 조건을 우회하지 않는다.

## 4. 이해

"1부에 죽음의 복선이 있다"와 "1부에서 죽었다"는 다른 말이다.
AI에는 앞 문장을 가능성/작가 계획으로, 독자가 실제로 읽은 죽음 장면은 사건으로
구분해 전달해야 한다. 이 수정은 그 경계를 저장과 실행 모두에서 유지한다.
실제 모델의 문체·인물·시간선 품질을 보장하는 만능 검사는 아니며,
본문 생성 시험과 작가의 검수를 따로 통과해야 한다.
